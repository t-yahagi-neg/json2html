# json2html

ローカルの動作確認用ページと生成物はGit管理対象外です。自動テストと、その実行に必要な`tests/fixtures`は管理対象に残しています。以下のディレクトリ構成にあるデータ・HTMLは利用時の配置例です。

`generate.py [ROOT]`で配下の`table.json`を再帰的に探し、各ページの`menu.json`・`menu.html`・`index.html`を一括生成するPython検証ツールです。`ROOT`の省略時は、スクリプトの配置場所ではなく実行時のカレントディレクトリが対象です。`add_empty_row.py`では、現在の列定義に対応した空データ行を`table.json`へ追加できます。

通常のHTML生成・閲覧には外部パッケージやビルド用ツールは不要です。Chromeで検証した`file://`による直接閲覧ではローカルWebサーバーも不要ですが、全ブラウザーでの動作・永続保存を保証するものではありません。列の絞り込み・表示切り替え、メニューの縮小、ピン留めに同梱のJavaScriptを使います。すべてUTF-8（BOMなし）、LF改行です。テスト専用の依存関係は「自動テスト」を参照してください。

通常ページの既存の`menu.json`は自動生成内容で上書きします。手動で編集した項目は置き換わるため、必要な内容は実行前に別途保存してください。例外として、`pin_page`で指定したピン留め専用ページの`menu.json`は保持します（用途は「ピン留め」を参照）。

## メニューの縮小表示

左メニュー上部右の **«** ボタンでサイドバーを縮小できます。

- 縮小時は細いバーになり、メニュー iframe は非表示
- 再度 **»** で展開
- 状態は `localStorage`（`json2html.sidebar.collapsed`）に保存

実装: `js/sidebar-toggle.js`。

## 表の絞り込み表示（Excel 風）

`generate.py` 実行後の `index.html` で、**1行目（列名）は残したまま、2行目以降（データ行）を列ごとに絞り込めます**。

- 各列ヘッダ**右端の ▾ ボタン**をクリックすると、その列の値一覧がチェックリストで開く
- チェックのオン/オフで行の表示を切り替え（Excel のオートフィルターに近い操作）
- 複数列を同時に絞ると **AND** 条件
- 「すべて選択 / すべて解除」、パネル外クリック・Esc でパネルを閉じる
- 「すべてのフィルターをクリア」で全列をリセット
- 件数は表上のステータスに表示

### フィルター項目の見え方

| セルの種類 | フィルター項目 |
|------------|----------------|
| 通常文字列 / link / multiline | 表示テキスト（空は「(空白)」） |
| `type: color` かつ `color: black` | **黒**（色見本付き） |
| 色指定なし・空セル | **(空白)** |
| 未対応の color 値 | **なし**（空セル表示。仕様上は現状 black のみ対応） |

照合キーは HTML の `data-filter-value` / `data-filter-label` に出力しています。

実装: `js/table-filter.js`（外部 CDN・ビルド不要）。

### 列の表示と状態の保存

- 列表示パネルのチェックリストで列を表示・非表示にします。表示ラベルは`column_options`で指定できます。
- 先頭列は常に表示し、チェックボックスは操作不可です。ヘッダー行も非表示にしません。
- パネル内の「初期表示に戻す」で、設定から決まる初期表示列へ戻します。
- `hidden_column_filter: "clear"`（既定）では、列を隠すとその列のフィルターを解除します。`"keep"`では維持し、非表示列で絞り込み中であることをステータスに表示します。
- フィルターと表示列はページ別に`localStorage`（ブラウザー内の保存領域）へ可能な範囲で保存します。HTMLの再生成ではブラウザーの保存内容は消えません。
- 保存できるかどうかはブラウザー・プライバシー設定に依存します。特に`file://`での直接表示はブラウザー依存です。保存不可でも操作はできますが、再表示後の復元は保証しません。設定の初期表示を変更した後は、保存済みの表示状態が優先されるためパネル内でリセットしてください。

## HTML生成

単一ページでも、そのディレクトリをROOTにして実行します。子ディレクトリに`table.json`があれば併せて処理します。

```zsh
cd /Users/shizuku/opt/projects/ValidationScripts/test_dir/json2html
python3 generate.py
```

別の場所から実行するときは対象ROOTを明示できます。

```zsh
python3 /Users/shizuku/opt/projects/ValidationScripts/test_dir/json2html/generate.py /Users/shizuku/opt/projects/ValidationScripts/test_dir/json2html
```

親ディレクトリからまとめて生成する例です。この場合、ROOTは`test_dir`となり、設定とメニューの探索範囲も変わります。

`pin_page`はコマンドのROOT以下にある各`json2html.config.json`で認識します。この例でも`json2html/json2html.config.json`の`"pin_page": "./pins"`が使われ、同梱の設定を変更する必要はありません。ピン留めのページIDと保存先は設定ディレクトリ基準なので、`json2html`をROOTにした場合と変わりません。専用ページの手編集済み`menu.json`も保持します。CSS・JSや表示設定の継承、自動メニューの探索範囲は従来どおりコマンドのROOTに従います。

```zsh
cd /Users/shizuku/opt/projects/ValidationScripts/test_dir
python3 json2html/generate.py
```

- 隠しディレクトリ（名前が`.`で始まるもの）、シンボリックリンクのディレクトリ・ファイルは対象外です。
- 通常ページでは`menu.json`・`menu.html`・`index.html`を一時ファイルへ生成してからまとめて置き換えます。途中で失敗したら、そのページの3ファイルを実行前の状態へ戻します（ロールバック）。さらにピン留め専用ページの出力失敗時は、影響するピンスコープ単位で生成出力を実行前の状態へ戻します。ROOT全体を一括で戻す方式ではなく、他の独立したスコープは処理を継続します。復元処理自体の失敗もエラーとして報告します。専用ページの既存`menu.json`は上書きしません。
- 毎回、メニュー・継承設定などを含めて内容を再計算します。出力内容が既存と同一なら`SKIP`とし、ファイルと更新日時を変更しません。`table.json`の更新日時だけでは判断しません。
- 結果はページのパス付きの`OK`・`SKIP`・`ERROR`と、最後の件数集計で確認できます。
- 通常の不正なページはエラーとして新しい自動メニューから除外し、影響のないページは処理を続けます。ただし有効化した`pin_page`の設定不備や専用ページの欠落・不正は、出力の公開（生成ファイルの配置・置き換え）前に生成を停止します。専用ページの出力に失敗した場合は、それを参照する新しい通常ページを公開せず、同じ実行中に先に成功したページも含め、影響するスコープの生成出力を実行前へ復元します。他の独立したスコープは処理を継続します。出力や復元でエラーがあれば終了コードは非0です。
- `--dry-run`は今回の対象外です。

`table.json`・共通設定・ピン留め専用ページの`menu.json`を編集した後は、同じROOTでHTMLを再生成し、ブラウザーを再読み込みしてください。JSONの編集は再読み込みだけでは反映されません。画面でのピン留め・解除には再生成は不要です。

## `table.json`

`columns`の順番が表の列順です。列数は固定されておらず、列の追加・削除にスクリプト修正は不要です。列名は空文字と重複を禁止します。

```json
{
  "$schema": "./schema/table.schema.json",
  "title": "一覧",
  "columns": ["A", "B", "C"],
  "rows": [
    {
      "A": "通常文字列",
      "B": "",
      "C": {
        "type": "color",
        "color": "black"
      }
    }
  ]
}
```

`rows`の1要素が表の1行です。行内に列名のキーがなければ警告なしの空セルになります。`columns`に存在しないキーは無視して警告します。

### 通常文字列と空セル

文字列はHTMLエスケープして表示します。空文字は空セルです。

```json
{
  "A": "日本語",
  "B": ""
}
```

### リンクセル

```json
{
  "type": "link",
  "text": "Google",
  "url": "https://www.google.com/"
}
```

表リンクは`http://`と`https://`だけに対応し、`target="_blank"`と`rel="noopener noreferrer"`を付けます。表示文字列・URLの不足や未対応URLは、使用可能な`text`を通常文字列として表示して警告します。

### 黒塗りセル

```json
{
  "type": "color",
  "color": "black"
}
```

対応色は`black`だけです。未対応色は空セルとして表示して警告します。

### 複数行セル

`multiline`は`columns`上の最後の列だけで正式対応します。列名がFかどうかではなく、配列上の位置で判定します。

```json
{
  "type": "multiline",
  "lines": [
    "通常の説明",
    {
      "type": "link",
      "text": "公式サイト",
      "url": "https://example.com/"
    },
    "",
    "補足説明"
  ]
}
```

- 文字列は通常行です。
- `type: "link"`は行全体がクリック可能なリンク行です。
- 空文字は先頭・途中・末尾を問わず空行として保持します。
- `lines`内で使用できるのは文字列とリンクオブジェクトだけです。
- 複数行内の各表示値とURLもHTMLエスケープします。

最後以外の列で`multiline`を使った場合は警告し、各行を通常文字列として表示してリンクを生成しません。

## 自動メニュー（`menu.json`）

各ページのメニューは、ROOT内の有効な`table.json`があるディレクトリだけから生成します。通常ページの`menu.json`は実行のたびに再作成します。ピン留め専用ページだけは既存の`menu.json`を保持し、表示時にブラウザーの登録状態を反映します。ヘッダーはありません。

通常ページのリンクの順番は次のとおりです。

1. ピン留め専用ページ（`pin_page`が有効な場合だけ、登録状態と無関係に常に先頭）
2. 直近の親ディレクトリ
3. 自分を除く兄弟ディレクトリ（ディレクトリ名の辞書順）
4. 直下の子ディレクトリ（ディレクトリ名の辞書順）

専用ページへのリンクは親・兄弟・子の枠へ重複表示しません。専用ページ自身のメニューは、直近の親ディレクトリにある有効なページと、ブラウザーで実際にピン留めしたページだけです。専用ページ自身を登録しても自己リンクは表示せず、未登録の兄弟・子ページも表示しません。直近の親が有効なページでなければ親リンクはなく、祖父母へ繰り上げません。

メニューの行枠は利用可能幅から約16px縮めた同じ幅とし、親・ピン関連（専用ページへのリンクと専用メニューの登録済みリンク）は左、同階層の兄弟は中央、子は右へ配置します。左端からの位置はそれぞれ約0／8／16pxです。文字揃えではなく行枠の位置を変え、リンクの順番は変えません。

ROOTの外は参照せず、自分自身へのリンクは作りません。親に`table.json`がなくても祖父母へ繰り上げません。子に`table.json`がなくても孫を直下の子として扱いません。ただし孫自身のページは再帰探索で生成対象になります。関係するページがなければ`items`は空配列です。

以下はすべてのディレクトリに有効な`table.json`があり、`00/`をコマンドのROOTとし、同ディレクトリの設定に`"pin_page": "./pins"`がある場合の対応です。入れ子の別スコープはないものとします。無効時は通常の親・兄弟・子だけになります。

| ページ | メニューのディレクトリ順 |
| --- | --- |
| `00/`（ROOT） | `pins`, `001`, `002`, `003` |
| `00/001/` | `pins`, `00`, `002`, `003` |
| `00/002/` | `pins`, `00`, `001`, `003`, `0021`, `0022` |
| `00/002/0021/` | `pins`, `002`, `0022` |
| `00/002/0022/` | `pins`, `002`, `0021` |
| `00/003/` | `pins`, `00`, `001`, `002`, `0031` |
| `00/003/0031/` | `pins`, `003` |
| `00/pins/` | `00` → ブラウザーでピン留めしたページ |

各項目の`type`は`link`、`text`はリンク先の有効なタイトル、`url`はそのページからリンク先`index.html`への相対パスです。例えば子ページから親への項目は次の形式になります。

```json
{
  "items": [
    {
      "type": "link",
      "text": "親の一覧",
      "url": "../index.html"
    }
  ]
}
```

リンクには`target="_top"`を付け、リンク先をiframe内ではなくページ全体へ表示します。従来のメニュースキーマには`type: "text"`もありますが、自動生成する項目はリンクのみです。

## ピン留め

### 専用ページの指定

コマンドのROOTまたはその配下の`json2html.config.json`に`"pin_page": "./pins"`を指定します。パスは、その値を宣言した設定ファイルのディレクトリを基準に解決します。指定先はそのディレクトリ自身または配下にあり、有効な`table.json`が既に存在する**ディレクトリ**です。`./pins/table.json`や`./pins/index.html`などのファイル、URL、絶対パス、設定ディレクトリの配下から外れる参照は指定できません（コマンドのROOT内であっても不可）。シンボリックリンクを経由する参照や、シンボリックリンクの`table.json`も禁止です。スキーマでは型・相対パス形式を確認し、存在・種別・参照範囲・シンボリックリンクの有無は生成時に確認します。

空でない`pin_page`は、設定ディレクトリとその子孫を対象とするピンスコープ（ピン留めの適用範囲）を開始します。子の設定に空でない`pin_page`があれば、そこから独立したスコープを開始し、各ページには最も近いスコープを適用します。省略・`null`・`""`は新しいスコープを作らず、既存の親スコープを継承します。親スコープもない場合だけ機能は無効です。専用ページは宣言元と同じスコープに属する必要があり、途中や専用ページ自身の設定で別スコープになる場所は指定できません。

`table.json`に書いた`pin_page`は使いません。`table.json`のスキーマにも追加していません。専用ページの自動探索は行いません。

ピン留めにとってコマンドのROOTは探索境界であり、ページIDの基準ではありません。`current_id`（現在のページID）はスコープを宣言した設定ディレクトリ基準で、`store_url`（保存用ページへのURL）はそのスコープの専用ディレクトリ内の`pin-state.html`を指します。同じファイル配置・設定なら、設定ディレクトリから生成しても、その親からまとめて生成しても両者は変わりません。複数プロジェクトや入れ子のスコープは、それぞれ独立したページカタログ（登録対象の一覧）とスコープ内で共有する保存先を持ち、別スコープの登録を混在させません。

ただし、設定ディレクトリより内側の子階層をROOTにすると、従来どおりROOTより上の設定は読みません。その親のピンスコープは引き継がれず、ROOT以下に別の空でない`pin_page`がなければピン留めは無効です。親スコープを維持するには宣言元の設定ディレクトリまたはその祖先をROOTにしてください。CSS・JSと表示設定の継承・探索はピンスコープで区切らず、引き続きコマンドのROOTを境界とします。

有効な値を指定したのに専用ディレクトリや有効な`table.json`が存在しない場合、または設定が不正な場合は、公開前に生成を停止します。無効化として処理を続けることはありません。有効時は各ページで解決された`assets.js`ディレクトリに`page-pins.js`も必要です。専用ページと保存用ファイルを先に出力し、その出力に失敗した場合は、それを参照する新しい通常ページを公開しません。

内部の`pin_transaction.py`にある`ScopeHistory`（スコープ単位の出力履歴）は、影響するスコープの生成ファイルを実行前へ戻すために使います。同じ実行中に通常ページの出力が先に成功していても、その後の再試行で専用ページの出力に失敗した場合は、成功済みの出力を含めて実行前の状態へ復元します。他の独立したスコープは処理を継続します。復元処理自体に失敗した場合もエラーとして報告し、完全に復元できたとは扱いません。

### 画面での登録・解除と保存

- 「すべてのフィルターをクリア」の隣にあるボタンで、表示中のページをピン留め・解除します。専用ページ自身にも同じボタンがあり、自身を登録・解除できます。有効なスコープ内の通常ページのメニュー先頭には、登録状態と無関係にそのスコープの専用ページへのリンクを表示します（専用ページ自身には登録済みでも自己リンクなし）。
- 登録済みは青背景・白文字の「ピン留めを解除」、未登録は灰色の「ピン留め」で示します。画面とメニューの通常の状態・成功メッセージは表示しません。初回読み込み・保存中はボタンを無効にし、保存失敗や保存データの破損などのエラー・警告だけを表示します。
- 専用ページのメニューは直近の有効な親ページと、自身を除く登録済みリンクだけです。各行に解除ボタンはなく、解除する対象ページへ移動してクリア隣のピン留めボタンを操作します。ドラッグによる並べ替えUIはありません。
- 状態は、同じスコープの全ページが同じ非表示iframe（埋め込みページ）を介して`localStorage`（ブラウザー内の保存領域）へ保存します。保存用ファイルは設定した専用ディレクトリ配下の`pin-state.html`（同梱例では設定ディレクトリ`json2html`基準で`pins/pin-state.html`）です。スコープ内の各ページからこの同じファイルを相対パスで参照し、別スコープとは保存先を分けます。生成される内部ファイルなので、直接開いたり手編集したりする必要はありません。
- Chromeの`file://`による直接表示でも、同じ保存用iframeを使ってページ間で状態を共有します。ただし保存の可否はブラウザー・プロファイル・プライバシー設定に依存します。保存を拒否された場合は利用不可を表示し、保存できた扱いにはしません。
- 保存が利用可能で、同じファイル配置・ブラウザープロファイルを使う場合、ページ移動・再読み込み・HTML再生成後もピン留め状態を保持します。保存データの削除や別ブラウザーへの切り替えでは引き継がれません。
- ブラウザーからディスク上のJSONを編集しません。ピン留め状態を`menu.json`へ自動転記することも、別ブラウザーへ同期することもありません。
- 登録状態はページID（ページを一意に識別する値）ごとに独立して保存し、1回の操作では対象ページの保存項目だけを更新します。異なるページの操作で他ページの登録状態を上書きしません。同じページを複数タブで同時操作する場合は、最後に保存された操作の状態になります。

### 専用`menu.json`の並び順ヒント

同梱の`pins/menu.json`は`{"items": []}`から始まり、親ディレクトリをROOTにした一括生成でも手編集した内容を保持します。同じスコープの既存ページへの`type: "link"`項目を手入力すると、HTML再生成後に**実際にピン留め済みのページだけ**の並び順のヒントとして使えます。`url`は専用ページから対象の`index.html`への相対パスです。例えば`../002/0021/index.html`を`../001/index.html`より先に記載すれば、両方が登録済みのときにその順を指定できます。

ここへの記入はピン留め登録ではありません。未登録ページは表示されず、生成対象として知られていないページ・外部URL・スコープ外の参照（同じROOT内の別プロジェクトや入れ子の別スコープも含む）は拒否または無視され、ヒントとして採用されません。登録・解除は画面のボタンで行ってください。

## タイトルの変更

`table.json`の`title`でページと自動メニューの表示名を指定します。省略・`null`・空文字の場合は、そのページのディレクトリ名を使います。共通設定には`title`を指定できません。

## 共通設定とページ別の上書き

任意の`json2html.config.json`をROOTや子ディレクトリに配置できます。ROOTからページへ順に、最後にそのページの`table.json`の値を重ねます。ROOTより上の設定は継承しません。途中のディレクトリに`table.json`がなくても、そのディレクトリの共通設定は子孫へ継承します。

継承する表示用の共通設定は`assets`・`alignment`・`column_options`・`hidden_column_filter`・`show_warnings`です（エディター用の`$schema`も可）。オブジェクトはフィールドごと、列設定は列キーとフィールドごとに継承します。別枠の`pin_page`はROOT以下の各共通設定でスコープを定義し、最も近いスコープを使います。`table.json`では上書きできません。ピンスコープが変わっても、表示設定は従来どおりROOTから継承します。

同梱の設定例はヘッダー中央・本文左寄せ、従来どおりの警告表示（`show_warnings: true`）、ピン留め専用ページを明示します。

```json
{
  "$schema": "./schema/config.schema.json",
  "pin_page": "./pins",
  "assets": {
    "css": "./css/style.css",
    "js": "./js"
  },
  "alignment": {
    "header": "center",
    "body": "left"
  },
  "hidden_column_filter": "clear",
  "show_warnings": true
}
```

### 空値と互換性

継承する設定項目は省略・`null`・空文字を許容し、継承値または既定値を使います。オブジェクトの`{}`も継承を消去しません。`visible: null`や`visible: ""`も同様で、`false`だけが明示的な非表示です。`pin_page`の省略・`null`・空文字も親スコープを解除せず、新しいスコープを作りません。親スコープがない場合だけ機能は無効です。これは既存の`columns`・`rows`・セル形式の制約を緩めるものではありません。`columns`は従来どおり文字列の配列です。

### CSS・JavaScriptの共有

- `assets.css`は相対ローカルパスのCSSファイル、`assets.js`は`table-filter.js`と`sidebar-toggle.js`の両方を含む相対ローカルパスのディレクトリです。`pin_page`が有効な場合は`page-pins.js`も必要で、各ページで解決されたディレクトリに存在するかを公開前に確認します。不足があれば生成を停止します。URLや絶対パスは指定しません。
- 相対パスの基準は、そのフィールドを宣言したJSONの置き場所です。ROOTの設定にある`./css/style.css`を子ページが継承しても、子ページの`./css/style.css`へ読み替えません。
- 設定で指定しない場合は、ページ自身からROOTまでの最寄りの`css/style.css`と`js`をそれぞれ探索し、見つからなければ生成スクリプト同梱のものを使います。ROOTより上は自動探索しません。
- ページ生成時に各参照先へのパスを調整するため、ページごとにCSS・JavaScriptをコピーする必要はありません。

### 配置・列ラベル・初期表示

`alignment.header`と`alignment.body`は、それぞれヘッダーと本文の配置です。値は`left`（左）・`center`（中央）・`right`（右）。列別の`header_align`・`align`があれば全体設定より優先します。継承を含めて配置指定がない場合は、従来の中央寄せ（複数行セルは左寄せ）を維持します。同梱設定は明示的に本文を左寄せにする点に注意してください。

次は`table.json`へ追加する設定の抜粋です。実際のファイルには`columns`と`rows`も必要です。

```json
{
  "column_options": {
    "A": { "label": "識別子", "header_align": "center", "align": "left", "visible": true },
    "B": { "label": "参照先", "visible": false }
  },
  "hidden_column_filter": "keep"
}
```

`label`は表示名だけを変更し、`columns`や行データのキーは変更しません。ラベル未設定時は継承ラベル、なければ元の列名です。表示未設定時は継承値、なければ表示となります。先頭列は設定や保存済み状態によらず必ず表示します。

## `table.json`へのシンボリックリンクの集約

元パスと先パスを指定し、配下の`table.json`へのシンボリックリンク（元ファイルを参照するリンク）を先パス直下にまとめます。次の2つのパスだけを変更して実行できます。元のJSONやHTMLは変更しません。

```zsh
SOURCE_DIR="/Users/shizuku/opt/projects/ValidationScripts/test_dir/json2html"
LINK_DIR="/Users/shizuku/opt/projects/ValidationScripts/test_dir/table-links"
python3 /Users/shizuku/opt/projects/ValidationScripts/test_dir/json2html/link_tables.py "$SOURCE_DIR" "$LINK_DIR"
```

元パス直下の子ディレクトリを1階層目とし、2階層目からファイル名の先頭に`_`を1つずつ増やします。元パス自身の`table.json`も、元ディレクトリ名で対象に含めます。

| 元パスからの位置 | 作成するリンク名 |
| --- | --- |
| `table.json` | `json2html.json`（元ディレクトリ名） |
| `001/table.json` | `001.json` |
| `002/0021/table.json` | `_0021.json` |
| `002/0021/detail/table.json` | `__detail.json` |

- リンク先は元の`table.json`の絶対パスです。元ファイルを移動するとリンクは切れます。リンク経由で編集すると元ファイルが変更されます。
- 先パスがなければ作成します。元パスと先パスが同じ場合はエラーです。先パスが元パスの配下にある場合、その先パス内は探索しません。
- 元パス配下のディレクトリや`table.json`自体がシンボリックリンクの場合は探索・作成対象から除外します。
- 同じ名前になる元ファイルが複数ある場合や、先パスに別のファイル・リンクがある場合は、作成前の確認でエラーにして上書きしません。同じ対象へのリンクが既にあれば`SKIP`になるため、再実行できます。
- 元ファイルの削除・改名後に不要になったリンクは自動削除しません。

## 空データ行の追加

`add_empty_row.py`は従来どおりスクリプトと同じ場所の`table.json`だけを更新します。一括生成のROOT指定とは別です。対象ファイル指定の追加は今回の対象外です。以下は`json2html`ディレクトリで実行します。

末尾へ追加:

```zsh
python3 add_empty_row.py
```

指定位置の既存行の前へ追加:

```zsh
python3 add_empty_row.py --position 3
```

`--position`は1始まりで、有効範囲は`1`から現在の行数`+1`です。省略すると末尾へ追加します。

追加行は現在の`columns`を読み取って自動生成します。

```json
{
  "A": "",
  "B": "",
  "C": ""
}
```

JSONは`ensure_ascii=False`、スペース2個のインデント、末尾改行付きで保存します。日本語、既存行、不要なキーは維持します。一時ファイルを再解析してから`os.replace()`で置き換えるため、検証・保存失敗時は元の`table.json`を保持します。

## 警告と致命的エラー

未定義列、未対応セル形式、リンク不備、未対応色、最後以外の列の`multiline`、不正なメニュー項目などは警告です。HTML生成を続行し、終了コードは`0`です。

`show_warnings`は警告欄を表示する真偽値（`true`・`false`）で、既定値は`true`です。警告がある場合、既定では次の領域に表示します。

- `table.json`の警告は`index.html`の`data-messages`領域
- `menu.json`の警告は`menu.html`の`menu-messages`領域

警告欄を非表示にするには、共通設定の`json2html.config.json`またはページの`table.json`に次の項目を追加します。以下は設定の抜粋です。`table.json`では既存の`columns`と`rows`も保持してください。

```json
{
  "show_warnings": false
}
```

ROOTから下位の共通設定を順に継承し、最後にページの`table.json`で上書きします。省略・`null`・空文字は継承値を使い、継承値もなければ`true`です。`false`で抑制するのは表とメニューのHTML警告欄だけで、警告の検出、CLI（コマンド実行時の出力）の警告件数、致命的エラーの扱いは変わりません。

設定変更後は`python3 generate.py [ROOT]`でHTMLを再生成してください。ブラウザーの再読み込みだけでは反映されません。

読み込み失敗、JSON構文エラー、必須構造の不備、空・重複列名、不正な新規設定、出力失敗はエラーです。JSON構文エラーでは行番号と列番号を確認できます。通常は不正なページの既存出力を保持し、影響のないページは継続します。共通設定のエラーはその設定を継承するページにも影響します。ただし、有効化した`pin_page`の設定不備・専用ページの欠落や不正・必要な`page-pins.js`の不足は公開前に生成を停止します。専用ページの出力失敗時は、それを参照する新しい通常ページを公開せず、影響するスコープの生成出力を実行前へ復元し、他の独立したスコープは継続します。復元処理自体の失敗もエラーとして報告します。エラーがあれば終了コードは非0です。`table.json`がないディレクトリはページ候補ではありません。

## JSON SchemaとVS Code

JSON Schema（JSONの構造を定義するファイル）はエディターでの入力検証用です。`.vscode/settings.json`で`**/table.json`・`**/menu.json`・`**/json2html.config.json`を関連付け、ネストしたファイルにも適用します。`json2html`をVS Codeのワークスペースとして開く前提です。別の場所をワークスペースにする場合は関連付けのスキーマパスを合わせてください。

`$schema`で直接指定する場合は、そのJSONからスキーマへの相対パスを使います。子ディレクトリでは例えば`../schema/table.schema.json`です。生成された`menu.json`に`$schema`がなくても、ファイル名の関連付けで検証できます。

VS Codeでは次を編集時に検出できます。

- 必須項目不足
- 型の違い
- 未対応の`type`
- 余分なプロパティ
- 不正なJSON構文

最後の列だけ`multiline`を許可する動的条件やURL形式、新規設定キー・値・参照先の検証は`generate.py`内の明示的なチェックでも行います。実行時にJSON Schemaを読み込む方式ではなく、外部の`jsonschema`パッケージは使用しません。エディターの構造検証と実行時の警告・エラーは役割が異なります。
